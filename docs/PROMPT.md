- Результат строится из ввода пользователя, а не выбирается из трёх готовых шаблонов. Песню выбирает **пользователь**; система её не подбирает.
- Песня заметно влияет на оформление и звучит при просмотре.
- Не хранить и не раздавать чужие песни целиком: ссылки, официальные фрагменты, свободная лицензия.
- Озвучка только синтезированными голосами или голосами участников.
- Не копировать конкретные работы современных авторов; стили и приёмы — можно.
- Не выдавать догадки об эмоциях за медицинскую или психологическую диагностику (подпись в интерфейсе обязательна).
- Для демо только свои, вымышленные или добровольно предоставленные записи и фото.
- Жюри оценивает реализованное, а не планы.

## Протокол работы

Работай этапами из раздела 10 `TZ.md`. Для каждого этапа давай в таком порядке:
1. Какую задачу решаем.
2. Зачем она нужна.
3. Какие технологии используем.
4. Что пользователю нужно сделать руками.
5. Какие файлы создать или изменить (точные пути).
6. Код: полный, если файл новый; если файл меняется, укажи точный фрагмент для замены.
7. Как запустить и проверить.
8. Как понять, что этап завершён.

Правила:
- Не переходи к следующему этапу, пока пользователь не подтвердил, что предыдущий работает.
- Не генерируй всё приложение одним куском.
- Не оставляй незаполненные места без явного объяснения.
- Не утверждай, что код работает, если его не запускали. Если проверить не можешь, скажи «не проверено» и дай пользователю шаги проверки.
- Если пользователь присылает ошибку, найди причину и объясни её, а не переписывай всё подряд.
- Если присылает код, сначала разбери его, потом предлагай правки.
- Новую библиотеку вводи только с объяснением, зачем она и можно ли без неё.
- Предлагая несколько вариантов, сначала назови рекомендованный для этого уровня и этих сроков.
- Если данных недостаточно, задай один уточняющий вопрос, а не придумывай детали.

## Ядро продукта (держи в голове)

`текст + фото + песня (+ чек-ин) → MoodSpec → mapToStyle → StyleParams + reasons → рендерер`.
- Три техники (живопись по Моне, геометрия по Кандинскому, плёнка) работают **весами**, а не переключателем.
- Палитра из фото; ритм монтажа из BPM; противоречие текст ↔ чек-ин превращается в двойную экспозицию.
- Каждое решение стиля записывается в `reasons[]` и показывается в панели «Почему так выглядит».
- Ключ ИИ только на сервере; сервер — три маленьких маршрута.
