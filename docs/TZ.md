## 0. Как читать

- **Must** — без этого прототип не сдаём. **Should** — делаем, если Must закрыт и есть время. **Won't** — сознательно не делаем.
- «Готово, когда» везде проверяемо: число, действие или результат, который можно показать.
- Техтермины объясняются в глоссарии (раздел 15). Пользователь — новичок.

## 1. Цель и принцип

Веб-приложение-дневник. Человек описывает день, прикладывает фото и песню (плюс короткий эмоциональный чек-ин). Система превращает это в **воспоминание**: вертикальную анимированную сцену с музыкой, названием и подписью, и сохраняет в **папку дня**. Все дни складываются в **архив**. Через год, открыв запись, человек должен снова почувствовать день.

**Принципы:**
1. Результат строится из ввода пользователя, а не выбирается из трёх готовых шаблонов. Стили смешиваются непрерывно (веса), палитра берётся из фото, ритм из песни.
2. Дневник — серия: постоянные элементы одинаковы во всех днях, меняются только переменные.
3. У каждого решения есть объяснение («Почему так выглядит»).
4. Приложение интерпретирует, а не диагностирует: нигде не выдаём догадки за психологическую или медицинскую оценку.
5. Работающий MVP важнее количества функций. Три сильных дня лучше десяти нестабильных функций.

## 2. Как концепция сверена с брифом хакатона

Исходная концепция (Emotional Experience Reconstruction) шире брифа. Ниже — что берём, во что превращаем, что откладываем, и почему.

| Элемент концепции | Решение | Приоритет | Почему |
|---|---|---|---|
| Дневник (текст) | Берём как есть | Must | Требование брифа |
| Фото | Берём, 1–6 штук | Must | Требование брифа |
| Песня | **Выбирает пользователь** (ссылка или файл) | Must | Бриф требует песню от пользователя. Идея «система подбирает музыку» противоречит брифу |
| Эмоциональный чек-ин (5 вопросов, мультивыбор эмоций) | Берём, необязательный шаг на ~20 с | Must (как опциональный ввод) | Дёшево, усиливает «связь ввода и результата», даёт противоречия («радостно, но пусто»), которые превращаем в визуальную идею |
| Emotional Profile | Это наш **MoodSpec** (расширенный, мультиметка) | Must | Единый контракт между модулями |
| Multimodal Fusion | Детерминированные правила слияния (раздел 8.6) | Must | Объяснимость, воспроизводимость |
| Music-Memory Matching | Превращаем в **объяснение влияния песни**: «песня медленнее дня, поэтому…» | Must | Бриф: песня должна влиять на оформление, а не просто быть рекомендацией |
| Подбор песни системой | Won't | — | Против брифа и лишний риск |
| Cinematic Direction Engine | Берём как **mapToStyle** (эмоция → кинорешения) | Must | Это наше «сердце» |
| Генерация видео через Higgsfield / Runway / Kling | **Won't в ядре.** Кинематографичность делаем в браузере: движение камеры, зерно, засветы, двойная экспозиция | — | Минуты генерации, цена и доступ API неизвестны, лица в личных фото искажаются, результат выпадает из визуальной системы. Бриф: «сам по себе AI баллов не даёт» |
| Физиологический контекст (пульс, HRV) | Только **демо-данные или импорт JSON**; рисуем как тонкую «линию пульса дня»; не влияет на эмоции | Should | Бриф запрещает выдавать догадки за диагностику; «контекст, а не проверка» |
| Eye tracking | Won't | — | Ненадёжно, не нужно |
| Название дня | Берём, 3–7 слов, один тон | Must | Требование брифа |
| Озвучка | Берём как Should, только синтезированные голоса | Should | «Плюс» в брифе |
| Архив + папка дня | Берём | Must | Требование брифа |
| Приватность (согласие, удаление) | Берём | Must | Раздел «Важно» брифа |

## 3. Пользовательский сценарий и экраны

**Язык интерфейса: русский.**

1. **Экран «Новый день»** (`/`)
   - Поле текста (≥20 символов, свободная форма).
   - Загрузка фото (1–6), превью.
   - Песня: вкладки «Ссылка» (Spotify/YouTube) и «Файл» (mp3/m4a/wav). Для ссылки доступны необязательные поля «Исполнитель — название», «Год», «Жанр».
   - **Чек-ин** (сворачиваемый блок, необязателен): насыщенность дня 1–5; эмоции — мультивыбор чипов (до 3); внутреннее напряжение 1–5; удовлетворённость днём 1–5; «хотел бы пережить снова» 1–5.
   - Необязательно: «Данные пульса» — кнопка «Подставить демо» / загрузка JSON (Should).
   - Галочка согласия на отправку текста и уменьшенных фото в ИИ-анализ. Без согласия работает локальный запасной анализ.
   - Кнопка «Собрать воспоминание» и шаги прогресса: «Читаю текст → Смотрю фото → Слушаю песню → Рисую».
2. **Экран «Воспоминание»** (`/day/[id]`)
   - Плеер вертикальной сцены 9:16 с кнопкой Play (звук запускается только по клику).
   - Название папки, эмоциональная подпись, дата.
   - Вкладки: «Воспоминание», «Папка дня» (текст, фото, песня, озвучка), «Почему так выглядит».
   - Кнопки: «Скачать папку (ZIP)» (Should), «Удалить день».
3. **Экран «Архив»** (`/archive`)
   - Лента карточек по датам (превью-кадр + название + дата). Поиск по названию. Открыть любой день ≤3 клика.
4. **Первый запуск**: в архив загружаются 3–7 демо-дней из `public/demo/`.

- **Frontend** — то, что выполняется в браузере. **Backend (API routes)** — маленький код на сервере. Ему нужны только 3 маршрута; **ключ ИИ живёт только там**.
- Нет серверной базы и аккаунтов: дни хранятся в **IndexedDB** (встроенное хранилище браузера). Минус: архив привязан к устройству. Поэтому демо-дни зашиты в приложение.
- **Стек (зафиксирован, менять только с объяснением):** Next.js + TypeScript, обычный CSS с токенами дизайнера, Canvas 2D, Web Audio API, `zod` (проверка JSON), `idb-keyval`, `web-audio-beat-detector` (BPM), `jszip` (экспорт, Should). Хостинг: Vercel + GitHub. LLM: Claude API (модель в переменной `LLM_MODEL`, по умолчанию `claude-sonnet-5-5`, проверить доступность). Три.js/WebGL — Won't.

## 5. Контракты данных (`src/lib/schema.ts`)

Файл — единственный источник правды. Менять поля можно только все вместе и с обновлением фикстур.

```ts
type Emotion = "joy"|"nostalgia"|"calm"|"tenderness"|"excitement"|"pride"|
               "gratitude"|"wonder"|"melancholy"|"loneliness"|"tension"|"fatigue";

interface CheckIn {                       // необязательный ввод
  intensity: 1|2|3|4|5; emotions: Emotion[];   // до 3
  tension: 1|2|3|4|5; satisfaction: 1|2|3|4|5; wouldRelive: 1|2|3|4|5;
}

interface PhotoSpec {                     // считается в браузере
  count: number;
  palette: { hex: string; share: number }[];   // 5 цветов
  brightness: number; contrast: number; warmth: number; saturation: number; // 0..1
  visionNotes?: { light: string; scene: string };  // от LLM, если есть согласие
}

interface AudioSpec {
  title?: string; artist?: string; year?: number; genre?: string;
  bpm: number; bpmConfidence: number;     // 0..1
  energy: number; brightness: number;     // 0..1
  mode: "major"|"minor"|"unknown";
  source: "file"|"link"; estimated: boolean;   // true для ссылки
  embedUrl?: string;                      // для ссылки
}

interface PhysioContext {                 // Should
  kind: "demo"|"import"; avgHr: number; maxHr: number;
  series: { t: number; hr: number }[];    // ≤48 точек
}

interface MoodSpec {
  version: 1;
  emotions: { emotion: Emotion; weight: number }[];  // 1–3, мультиметка
  primary: Emotion; secondary?: Emotion;
  valence: number;                        // -1..1
  energy: number; tension: number; warmth: number;   // 0..1
  atmosphere: string;                     // 1–3 слова, «горько-сладкая»
  timeOfDay: "morning"|"day"|"evening"|"night"|"mixed";
  season: "winter"|"spring"|"summer"|"autumn"|"unknown";
  setting: string[]; people: string[]; keywords: string[];  // keywords 3–8
  title: string;                          // 3–7 слов
  narrationTone: "calm-warm"|"bright-fast"|"cool-precise"|"soft-quiet";
  contradiction: { present: boolean; note: string };
  confidence: number;                     // 0..1
  source: "llm"|"fallback";
  fusionNotes: string[];                  // для панели «Почему»
}

interface Reason { signal: string; effect: string; why: string;
                   from: ("text"|"photo"|"music"|"checkin"|"physio")[] }

interface StyleParams {
  palette: string[];                      // 5–6 hex, основа — фото
  grade: { hueShift: number; saturation: number; contrast: number };
  weights: { paint: number; geometry: number; film: number };  // сумма = 1
  camera: { zoomFrom: number; zoomTo: number; panAmp: number; shakeAmp: number };
  timeline: { duration: number; beatsPerCut: number; cutInterval: number;
              transition: "crossfade"|"cut"|"stroke-reveal"; cuts: number[] };
  grain: number; glow: number; vignette: number;      // 0..1
  doubleExposure: number; negativeSpace: number;      // 0..1
  strokes: { length: number; curvature: number; density: number };
  shapes: { density: number; angularity: number };
  typography: { weight: number; tracking: number };
  physioLine: boolean;
  reasons: Reason[];
}

interface DayRecord {
  id: string; createdAt: string; title: string;
  input: { text: string; photos: Blob[]; songFile?: Blob; songUrl?: string;
           checkIn?: CheckIn; physio?: PhysioContext };
  mood: MoodSpec; photo: PhotoSpec; audio: AudioSpec; style: StyleParams;
  voice?: Blob; poster?: Blob;
}
```

## 6. Визуальная система

**Постоянные элементы (одинаковы в каждом дне; проверяется пиксельно):**
- Холст 1080×1920 (9:16), рендер превью 540×960; безопасные поля 64 px.
- Рамка фото фиксированного формата 4:5, положение фиксировано.
- Дата вверху слева, название внизу, подпись внизу справа (рукописный шрифт).
- Шрифты (все SIL OFL, проверить кириллицу): Cormorant Garamond (заголовки), Inter (текст), Marck Script (подпись). Дизайнер может заменить, но набор остаётся постоянным.
- Финальный кадр: название + дата + подпись на 2 с.

**Переменные элементы:** палитра, цветокоррекция, веса техник, зерно, свечение, виньетка, двойная экспозиция, свободное пространство, штрихи, фигуры, ритм монтажа, движение камеры, толщина шрифта и разрядка.

**Художественные приёмы (для документа сдачи; каждый включается по сигналу):**

| Приём | Референс | Включается, когда | Почему передаёт ощущение |
|---|---|---|---|
| Живописные мазки и мягкий свет | Клод Моне | Тепло высокое, напряжение низкое, энергия низкая | Размытые границы и тёплые мазки передают покой и «растворение» времени |
| Геометрия линий и пятен | Кандинский | Напряжение и энергия высокие | Резкие углы, ритм и контрастные формы читаются как динамика и напряжение |
| Плёнка: зерно, засветы, ореол | Аналоговая фотография | Ностальгия, старая песня, «горько-сладкая» атмосфера | Зерно и ореол ассоциируются с памятью и прошлым |
| Двойная экспозиция | Коллаж, мультиэкспозиция | Противоречие между текстом и чек-ином | Два слоя в одном кадре показывают два чувства одновременно |
| Пустое пространство (ма) | Японский минимализм | Меланхолия, одиночество, низкая энергия | Воздух вокруг объекта даёт паузу и тишину |

## 7. Сквозные правила

- Все числа 0..1 (кроме valence −1..1, bpm и таймингов), все перемножения защищены `clamp(0,1)`.
- Любой фоллбек помечается в UI («оценочно»).
- ИИ-интерпретация эмоций сопровождается подписью: «Это интерпретация настроения, а не диагноз».
- Никаких секретов в репозитории; ключ только в `.env.local` (локально) и в переменных Vercel.

## 8. Модули: требования и критерии готовности

### 8.1 Ввод (Must)
- Валидация: текст ≥20 символов, фото 1–6 (jpg/png/webp, ≤10 МБ каждое), песня обязательна.
- Фото уменьшаются до 768 px по длинной стороне для анализа и отправки; оригиналы сохраняются локально.
- **Готово, когда:** без песни или без фото кнопка неактивна с понятным сообщением; форма отдаёт объект `{text, photos[], song, checkIn?, physio?}`.

### 8.2 Текстовый анализ (Must) — `/api/analyze`
- Принимает: текст, чек-ин (если есть), мини-фото (если есть согласие), метаданные песни.
- LLM получает **системное правило**: отвечать только JSON по схеме; не выдумывать события; допускать смешанные эмоции (1–3); при коротком или двусмысленном тексте снижать `confidence`; не ставить диагнозов; название — 3–7 слов, именная фраза, по-русски, без эмодзи и точки, единого тона.
- Ответ проверяется `zod`; при ошибке — один повтор; при повторной ошибке — запасной анализ на словаре ключевых слов (`source:"fallback"`).
- **Готово, когда:** 10 разных текстов дают 10 валидных ответов; название в границах 3–7 слов в 10/10; ответ <8 с; тест с обрывом сети выдаёт запасной MoodSpec без падения.

### 8.3 Чек-ин (Must, необязательный для пользователя)
- Хранится как `CheckIn`; участвует в слиянии (8.6).
- **Готово, когда:** выбор 3 эмоций одновременно работает; 4-ю выбрать нельзя; пропуск блока не ломает поток.

### 8.4 Анализ фото (Must) — браузер
- По уменьшенным кадрам считаем: 5 доминирующих цветов (простая квантизация или k-means на 64×64), яркость, контраст, теплоту (баланс R/B), насыщенность.
- Если есть согласие, LLM возвращает `visionNotes` (свет и сцена одной строкой).
- **Готово, когда:** для 6 тестовых фото `PhotoSpec` валиден; светлое тёплое фото даёт `warmth > 0.6`, ночное синее `warmth < 0.4`.

### 8.5 Анализ музыки (Must)
- **Файл:** декодируем через Web Audio, считаем BPM (`web-audio-beat-detector`), энергию (RMS), яркость (спектральный центроид). Лад — `unknown`, если нет надёжной оценки, или оценка LLM (помечается).
- **Ссылка:** `/api/song-meta` достаёт название и исполнителя через oEmbed; темп, лад, жанр, эпоху оценивает LLM (`estimated:true`). Воспроизведение через встроенный плеер (embed). Аудио с сервисов не скачиваем.
- **Готово, когда:** на 5 известных файлах BPM в пределах ±8% минимум у 4; порядок по энергии «медленная < средняя < быстрая» верен; ссылка без доступа к API всё равно даёт `AudioSpec` с `estimated:true`.

### 8.6 Слияние (Must) — `fuse.ts`, детерминированно
- `energy_text` и `tension_text` приходят от LLM. Если есть чек-ин: `tension = 0.6·text + 0.4·checkin`, интенсивность аналогично.
- **Противоречие:** если `|valence_text − valence_checkin| > 0.5`, ставится `contradiction.present = true`, `atmosphere` содержит «контраст» или «горько-сладкая», `confidence` снижается на 0.15. Это **не ошибка**, а входной сигнал для двойной экспозиции.
- Пульс (если есть) **не меняет** эмоции. Он включает `physioLine` и добавляется в `reasons` как «ритм дня».
- Каждое правило, которое сработало, добавляет строку в `fusionNotes`.
- **Готово, когда:** юнит-тесты на 4 кейса (согласие, противоречие, без чек-ина, с пульсом) проходят.

### 8.7 Cinematic Direction Engine (Must) — `mapToStyle.ts`
Нормализованные входы: `N` — вес «ностальгии», `W` — warmth, `T` — tension, `V` — valence, `E_m` — динамика движения.

`E_m = 0.5·audio.energy + 0.3·mood.energy + 0.2·checkin.intensity_norm` (если чек-ина нет, пересчитывается без него).

| Что считаем | Формула (стартовые значения, подбираются «на глаз») |
|---|---|
| Веса техник (до нормализации) | `paint = 0.45·W + 0.30·(1−T) + 0.25·(1−E_m)`; `geometry = 0.50·T + 0.30·E_m + 0.20·(1−W)`; `film = 0.50·N + 0.30·contradiction + 0.20·eraOld`. Каждый вес не ниже 0.05, затем сумма приводится к 1 |
| Ритм монтажа | `beatsPerCut = round(lerp(8, 2, E_m))`; `cutInterval = clamp(beatsPerCut·60/bpm, 1.0, 7.0)` с |
| Переход | `T>0.6 и E_m>0.5` → `cut` на бит; `E_m<0.4` → `crossfade` 1.2 с; `N>0.5` → `stroke-reveal` |
| Камера | `zoomDelta = lerp(0.03, 0.12, E_m)`; `panAmp` так же; `shakeAmp>0` только при `E_m>0.75` |
| Палитра | основа из `PhotoSpec.palette`; сдвиг оттенка `hueShift = (W−0.5)·24°`; насыщенность ×`(0.8+0.4·(V+1)/2)` |
| Зерно, свечение, виньетка | `grain = 0.10+0.50·film+0.10·N`; `glow = 0.6·N+0.3·W`; `vignette = 0.2+0.5·T` |
| Двойная экспозиция | `0.6`, если `contradiction.present`, иначе `0` |
| Свободное пространство | `negativeSpace = clamp(0.5·melancholy + 0.4·loneliness + 0.3·(1−E_m))` |
| Мазки | длина растёт с `(1−E_m)`, кривизна с `(1−T)`, плотность с `W` |
| Фигуры | плотность с `E_m`, угловатость с `T` |
| Шрифт | толщина `300 + 400·T`, разрядка шире при низкой энергии |

- Каждая строка таблицы пишет в `reasons[]` объект `Reason` на русском: «Медленная минорная песня (68 BPM) → смены кадров реже (≈6 с), больше воздуха».
- Правило `music`: в `reasons` должна быть минимум одна запись `from:["music"]`, объясняющая **влияние песни**, включая случай контраста («песня спокойнее дня, ритм монтажа от песни, а динамика камеры от текста»).
- **Готово, когда:** одна и та же запись с BPM 70 и 150 даёт заметно разный ритм (A/B запись экрана); 3 фикстуры дают 3 разных набора `weights`; в каждом дне ≥4 причины, ≥1 про музыку.

### 8.8 Рендерер (Must) — Canvas 2D + Web Audio
Слои снизу вверх: **background** (градиент палитры + текстура бумаги), **photo** (кадры в рамке с Ken Burns и сменой по `cuts`), **paint** (штампы мазков по цветам фото, раскрываются по времени), **geometry** (линии, круги, треугольники из SVG-набора, пульсируют на бит; если `physioLine`, тонкая линия пульса), **film** (зерно, засветы, ореол, виньетка, двойная экспозиция), **constants** (дата, название, подпись, рамка).
- Длительность 20–30 с. Музыка играет через `<audio>` или embed; для файла используется `AnalyserNode` (зерно и пульс фигур реагируют на амплитуду).
- Звук стартует только по клику Play.
- **Готово, когда:** сцена воспроизводится со звуком на 3 разных днях при ≥30 fps на среднем ноутбуке; нет ошибок в консоли; веса техник визуально различаются между днями.

### 8.9 Названия (Must)
- 3–7 слов, один тон (именная фраза, нейтральный и тёплый), без эмодзи. `validate.ts` проверяет длину и пунктуацию; при нарушении — до двух авторегенераций, затем запасное название из ключевых слов.
- **Готово, когда:** 20 тестовых текстов дают 20 названий в границах и в одном тоне.

### 8.10 Хранение и папка дня (Must)
- `DayRecord` сохраняется в IndexedDB. «Папка дня» — представление записи, в котором видны: текст, фото, песня (ссылка или файл), готовое воспоминание, озвучка (если есть), «Почему так выглядит».
- **Готово, когда:** после перезагрузки страницы день открывается из архива; удаление дня убирает его целиком.

### 8.11 Архив (Must)
- Лента по датам с превью-кадром (постер из рендера), поиск по названию.
- **Готово, когда:** при 7 днях любой открывается за ≤3 клика и воспроизводится с музыкой.

### 8.12 Панель «Почему так выглядит» (Must)
- Выводит `reasons[]` + `fusionNotes[]` языком, понятным человеку, сгруппированно: Текст · Фото · Музыка · Чек-ин · Пульс.
- **Готово, когда:** на каждом дне ≥4 причины и ≥1 причина про музыку; видны веса техник («живопись 60%, плёнка 30%, геометрия 10%»).

### 8.13 Озвучка (Should)
- Профиль голоса из `narrationTone`: `calm-warm`, `bright-fast`, `cool-precise`, `soft-quiet`. Старт — браузерный `speechSynthesis` (нулевой риск), затем TTS-сервис, если успеваем.
- Только синтезированные голоса или голоса участников; музыка приглушается на −12 дБ под речью.
- **Готово, когда:** два дня звучат заметно по-разному; озвучка сохраняется в папку.

### 8.14 Экспорт (Should)
- ZIP: `text.txt`, `photos/`, `song.txt` (ссылка и метаданные; аудиофайл только если он свободной лицензии), `poster.png`, `voice.mp3` (если есть), `why.md`. WebM-запись сцены — по возможности.
- **Готово, когда:** ZIP скачивается и распаковывается со всеми файлами.

### 8.15 Приватность и этика (Must)
- Галочка согласия перед отправкой текста и мини-фото в ИИ. Без неё — только локальный фоллбек.
- Кнопка «Удалить день» и «Очистить весь дневник».
- Подпись «Это интерпретация настроения, а не диагноз» в панели «Почему» и в README.
- Для демо используются только свои, вымышленные или добровольно предоставленные записи и фото; музыка — свободные лицензии или ссылки.

## 9. Нефункциональные требования

- **Надёжность:** без сети демо-дни открываются (предзакэшированы); при падении LLM воспоминание всё равно создаётся (фоллбек).
- **Производительность:** загрузка главной ≤5 с; рендер ≥30 fps; анализ фото ≤2 с на 6 снимков.
- **Совместимость:** Chrome (основной) и Safari; звук через кнопку Play.
- **Безопасность:** ключи только на сервере; нет секретов в git (`.env.example` без значений); лимит размера входа на сервере; на `/api/analyze` — простая защита от злоупотреблений (лимит запросов по IP или общий дневной лимит).

## 11. Порядок сокращений при срыве сроков

1. Озвучка TTS (оставить браузерный синтез или убрать). 2. WebM-экспорт (оставить PNG-постер). 3. ZIP-экспорт. 4. Физиологический контекст. 5. Свободное пространство и тонкая настройка шрифта. 6. Одну из техник (оставить две + параметрическая вариация).
**Не режем:** связь ввода и результата, музыку, объяснимость, архив, 3 разных дня, деплой, пакет сдачи.

## 15. Глоссарий (для новичка)

- **Frontend** — часть программы, которая работает в браузере и рисует интерфейс.
- **Backend / API route** — маленький серверный код; нужен, чтобы спрятать ключ ИИ.
- **API-ключ** — секретный пароль доступа к ИИ-модели; нельзя класть в браузерный код или в git.
- **JSON** — текстовый формат данных вида `{"energy": 0.7}`.
- **Схема / zod** — описание, как должен выглядеть JSON; zod проверяет, что ответ ИИ ему соответствует.
- **MoodSpec** — наша таблица параметров дня (эмоции, энергия, напряжение, теплота, название…).
- **IndexedDB** — встроенное хранилище браузера; хранит фото и данные на устройстве пользователя.
- **Canvas** — «холст» в браузере, на котором код рисует кадры.
- **Web Audio** — возможности браузера по работе со звуком (анализ, воспроизведение).
- **BPM** — удары в минуту, темп песни.
- **Деплой** — публикация сайта в интернете по ссылке.
- **Фоллбек** — запасной путь, если основной не сработал.
- **Ken Burns** — медленное приближение или панорама по неподвижному фото.
